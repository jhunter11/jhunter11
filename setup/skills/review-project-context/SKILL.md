# Review project context

Read the existing project memory and its repository instructions before changing it.
For each new fact, retain its source and the date it was checked.
Label proposals as proposals. Record a decision as approved only when the conversation or source establishes approval.

Resolve conflicts against the most recent applicable evidence.
If the sources disagree, keep the conflict visible until it can be resolved.
Do not infer that a test passed from an earlier run after the tested files have changed.

Keep durable context small enough to review.
Store large logs and experiment records separately, then link the useful evidence.
Record the next action with its dependencies so another agent can continue without repeating completed work.

Review generated context before sending it to an external service.
Keep project secrets and private records out of public templates.
Apply access controls to the storage itself. A memory label or scope name does not establish permission to read a record.
